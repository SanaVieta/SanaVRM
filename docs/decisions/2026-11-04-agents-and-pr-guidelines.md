# Decision: AGENTS.md and PR/decision-doc workflow

**Status:** accepted  
**Date:** 2026-11-04

## Context

The repo had only auto-generated Next.js agent rules in `AGENTS.md`. Contributors and coding agents lacked shared conventions for stack choices, RSC usage, Supabase/data UI patterns, and how to document decisions and PRs.

The product direction (see `docs/schema.md`) uses Shopify as commerce source of record with local CRM data—likely Next.js App Router plus Supabase—so agent guidance should match that stack and this repo’s tooling (Biome, Tailwind 4, Next 16 per `package.json`).

## Decision

1. **Expand `AGENTS.md`** with project-specific engineering rules while **keeping** the `nextjs-agent-rules` block required by `next dev`.
2. **Require decision docs** for meaningful architectural choices under `docs/decisions/` using a lightweight ADR shape (context, decision, alternatives, impact, status).
3. **Require structured PR descriptions**: summary, enumerated changes, impact, test plan, and links to decision docs when relevant.

## Alternatives considered

| Alternative | Why not chosen |
|-------------|----------------|
| Rely on Cursor user rules only | Not versioned with the repo; new clones and other agents miss them. |
| Single `CONTRIBUTING.md` only | Agents and tools prioritize `AGENTS.md`; split keeps human contrib docs optional later. |
| Strict `*.br` / skill paths in AGENTS | Belongs in `.gitignore` and setup docs, not coding standards. |
| Pin “Next.js 14” in AGENTS | Inaccurate for this repo (`next@16.x`); AGENTS references `package.json` as source of truth. |

## Consequences

- Agents and humans share one checked-in standard for code style, RSC bias, loading/error states, and Supabase-oriented data fetching.
- Non-trivial work carries traceable rationale in `docs/decisions/`.
- PR review is faster when every PR states **what changed** and **impact** explicitly.
- The Next.js block may still be regenerated by `next dev`; edits outside that block are maintained manually.

## Impact

- **Developers:** PR template expectations are documented in `AGENTS.md` (no GitHub template file added in this change).
- **Agents:** Read `AGENTS.md` before implementing features; create decision docs when changing architecture.
- **Ops:** None until Supabase/production wiring lands.
